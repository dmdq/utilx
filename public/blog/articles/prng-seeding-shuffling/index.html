随机数的工程学：mulberry32 种子复现同一份卷，与为什么不该用 sort 洗牌

技术笔记
2026-11-18有条工具团队

随机数其实是算出来的#

Math.random() 给人的错觉是「真随机」，真相是：它由一个确定性的算法从内部状态逐步算出——给定同样的初始状态，后面的序列一模一样。这类算法叫伪随机数发生器（PRNG）：用上一状态经固定的位运算搅动，产出一个「看起来无规律」的数，再把它当作下一轮的状态。所谓种子（seed）就是那个初始状态。

种子即复现密码。这个性质平时是 PRNG 的「缺陷」（可预测），在生成内容类工具里却成了功能：口算题卡生成器把「这份卷」压缩成一个数——同样设置 + 同一个种子 = 逐题相同的卷子。家长打第二份、老师隔年重出、客服排查「第 7 题印错」时精确还原现场，全靠它。站内题卡与字帖类工具用的是 mulberry32——三十来位运算的标准实现，状态仅一个 32 位整数，序列周期 2³²，质量对生成题目绰绰有余，速度比密码学级 PRNG 快两个量级。而 Math.random() 没有种子接口（状态不可注入），每次刷新都是新序列——要复现就只能自己带种子的 PRNG，这是「题卡用 mulberry32、抛硬币用 Math.random」的分工依据：前者要复现，后者要不可预测。

顺带一提分界线：涉及安全（令牌、密码）必须用 crypto.getRandomValues（密码学随机，不可预测、不可复现），mulberry32/Math.random 都不行——生成器家族选错场景是真实漏洞，不是风格问题。

抽牌不放回：splice 抽样即部分洗牌#

「从一副牌里抽 5 张、抽过的不再出现」——直觉实现是每次 Math.floor(Math.random() * deck.length) 取一张然后 splice 移除。这其实是正确的：等价于部分 Fisher-Yates 洗牌（只洗前 k 个位置）。等概率性可以证明：每张牌在每轮被抽中的概率均等，组合数上每种 k 张的组合同概率。站内抽卡工具的「不放回模式」走这条路，抽完的牌从余牌堆真实扣减，下次接着抽——牌桌语义完整。

sort 洗牌：一个流传最广的错误#

很多人以为「打乱数组」可以偷懒：

1

arr.sort(() => Math.random() - 0.5)   // ✗ 有偏洗牌

错在把「排序」用在了它不保证的事情上。比较排序要求全序且一致（a<b 的判断不能变卦），而随机比较器每次给出矛盾答案——排序算法在矛盾输入下的行为是实现细节：不同引擎、甚至同一引擎的不同输入长度，产出的排列分布都不均匀，某些排列系统性高频。经典实验：对 3 个元素这样「洗」一万次，本应各占 1/6 的六种排列，计数能差出数倍。正确的洗牌是 Fisher-Yates：从尾部往前，位置 i 与「0..i 中随机一个位置」交换——每个排列恰好等概率，O(n) 一遍完成，还比排序快。

1
2
3
4

for (let i = n - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1))   // 0..i 含端
  ;[arr[i], arr[j]] = [arr[j], arr[i]]
}

一个更细的坑叫模偏置：Math.floor(Math.random() * n) 在 n 不整除 2³²（或引擎的随机整数域）时，低位取值会多出一丝丝概率差——对抽牌抽奖无感，对密码学场景必须用拒绝采样修正。工程判断的口径：娱乐场景忽略，安全场景零容忍。
