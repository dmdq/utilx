零不良不等于零 DPPM：测试报告里的置信度账

生活工具
2026-11-05有条工具团队

两个都说"0 不良"的报告，含金量差一倍#

来料检验里最常见的争执：供应商报告"本批测试 0 不良"，你们抽检 200 只也是 0 不良，这批是不是就该放行？答案是：两个零不良给出的背书，比单看任何一份都强，但都不等于"真不良率为零"。

抽样检验服从二项分布：真不良率 p 的批次，抽 n 只全好的概率是 (1−p)ⁿ。反过来推，“抽 n 只全好"时，真不良率仍有 60% 的置信度落在某个上限之下——n=1000 时这个上限约是 916 DPPM，n=200 时约是 4590 DPPM。样本越小，同样"零不良"的背书越弱，这就是为什么正经的测试报告必须标注置信水平（行业惯例 60%），也是 DPPM 报表里"置信上限"那一栏存在的意义。

新工具：把三笔账一次算清#

上线的🔧 DPPM良率计算器 按 TI 可靠性计算器的口径实现，三块功能：

观测换算：总数、不良数填进去，出 DPPM 和良率；反向也给——客户要求 ≤500 DPPM，出货 5000 只最多允许 2 只不良，这种反向账谈规格时天天用。

置信上限：置信度 60%/90%/95% 三档，失效数支持非零。零失效时上限 = −ln(1−置信度)/n，有失效时按卡方分布上界算。自核锚点：n=1000、f=0、60% 置信 → 916 DPPM，这个数与 TI 官方计算器一致。以后供应商拿"零不良"说事，先问一句"按多少置信度算的上限”。

滚动良率：多道工序的总良率是连乘不是平均。CP 95% × FT 98% × 老化 99% ≈ 92.1%，对应约 79,000 DPPM——良率是乘法衰减的，单站 99% 听着很好，串十站只剩 90%。品质改善的资源永远该砸在最差的那一站，这个工具让"最差的那站"从直觉变成数字。

良率账的另一头：抽样方案和库存#

DPPM 是结果指标，管控它的前端是抽样方案。🔧 AQL抽样计算器 按 GB/T 2828.1（ISO 28585 同源）口径给字码、样本量和 Ac/Re 判定数，CR/MAJ/MIN 三条线分开判——来料检验的"抽多少、怎么判"在这头。

测试结果再往下游走一步就是库存账：🔧 安全库存再订货点 按 Z 值服务水平和提前期波动算补货点，🔧 EOQ 经济订货量计算器 算订货批量。来料不良率高 → 安全库存要多垫；测试良率上不来 → 呆滞风险涨——测试与库存这两本账用同一份品质数据。

几个概念，别再混着用#

DPPM 词条里专门澄清了三组容易混的概念：DPPM 管出厂/来料批次的不良比例，FIT 管使用中每十亿器件小时的失效率，一个"出厂质量"一个"现场可靠性"，不能互相换算；Cpk 管过程稳定度（≥1.33 是电子代工常见门槛），Cpk 好而 Ppk 差说明批次间在漂移，相关判定档在过程能力指数词条里。

三件质量工具（DPPM、AQL、安全库存）连同 EOQ 收在IC 测试质量台专题，按"成品测试 → 来料抽样 → 库存联动"的工作流排布。所有计算本地完成，良率数据不出浏览器——对品质部门来说，这句话比任何功能都重要。
