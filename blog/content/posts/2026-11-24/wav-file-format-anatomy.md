## 44 个字节的「文件头」，其实是三个 chunk

把一个 WAV 文件扔进十六进制查看器，开头永远是 `52 49 46 46`——ASCII 的 "RIFF"。RIFF（Resource Interchange File Format）是一种「块状」容器：每块 = 4 字节类型标记 + 4 字节长度 + 数据本体，长度字段只计数据不算头，块与块首尾相接形成链。WAV 文件就是 RIFF 容器里装了一个 "WAVE" 类型，里面再挂两个子块：

- **fmt 块**（16 字节本体）：描述音频参数——音频格式（1 = 纯 PCM，无压缩）、声道数、采样率、字节率、块对齐、位深；
- **data 块**：原始 PCM 采样数据，长度即字节数。

逐字节排开正是 44 个：`RIFF`(4) + 文件总长减 8(4) + `WAVE`(4) + `fmt `(4) + 16(4) + 十六个参数字节 + `data`(4) + 数据长(4)。这里藏着两个高频翻车点：**RIFF 头部那个长度字段是「文件总长 − 8」**（36 + dataSize），不是文件长度也不是数据长度；**所有整数都是小端**（little-endian，低字节在前）——`new DataView(buffer).setUint32(4, 36 + dataSize, true)` 里那个 `true` 就是小端开关，忘写的话默认大端，写出来的文件采样率会变成天文数字，播放器直接拒收。

fmt 块里最容易写错的是两个「派生字段」：**blockAlign** = 声道数 × 每样本字节数（16-bit 双声道就是 4），**byteRate** = 采样率 × blockAlign（每秒多少字节）。它们是纯冗余——都能从其他字段推出来——但规范要求必须填对，部分播放器拿 byteRate 做缓冲估算，填错会出现播放进度条诡异跳动的灵异现象。

## int16 量化：−32768 到 +32767 的不对称

WebAudio 内部用 Float32 存采样，取值 ±1.0；写进 WAV 要量化成 int16。这里有个值得单独讲的细节：**负方向比正方向多一格**。0 到 65535 的无符号区间映射到 −32768 到 +32767，所以 −1.0 应乘 0x8000（=32768）得 −32768，+1.0 只能乘 0x7FFF（=32767）得 32767——对称地都乘 32768 会让 +1.0 溢出到 +32768，int16 里这是负数。实现里就写成 `s < 0 ? s * 0x8000 : s * 0x7fff`，一个三元分支处理这对不对称。

量化前还要 **clamp**：浮点音频经过增益、混叠等处理后可能超出 ±1（比如两轨相加），直接 `(int16)(s * 32767)` 会回绕成完全错误的值——正溢出变负、波形「对折」，听感是爆音。先 `s > 1 ? 1 : s < -1 ? -1 : s` 钳回安全区，超界部分变成削顶方波（hard clipping），有损但不致命。顺带一提 dBFS 口径：±1.0 满量程对应 0 dBFS，所以「−12 dB 余量」= 振幅约 25%——对数刻度下的纪律。

**双声道的排布是交错的**（interleaved）：帧按 L、R、L、R 依次排列，不是「左声道全部数据 + 右声道全部数据」。编码循环是外层走帧、内层走声道——`for (frame) for (channel) write`，blockAlign=4 的含义正是「一帧 4 字节」。解码端同理拆交错，声道数对不上时按 fmt 块的声明切。

## 为什么音频工具都爱 WAV

WAV 的好处全在「**没有压缩**」：编码是纯字节拼接，不需要任何库；任何播放器、剪辑软件都能直接读。代价是体积——44.1kHz / 16-bit / 双声道的 CD 音质，每分钟约 10 MB。浏览器音频工具（倒放、静音切除、变速、拼接）的导出路径几乎清一色是「AudioBuffer（Float32）→ 徒手拼 WAV → Blob 下载」，44 字节头加上一段 DataView 循环，三十行代码换一个全平台通吃的输出格式。要瘦身再走编码器（MP3/OGG），那是另一条有损压缩的世界线。

RIFF 这个容器家族还有个近亲值得认识：AVI 与 WebP 的 RIFF 血统、PNG 的 chunk 链（类型+长度+数据+CRC32），都是同一个「自描述块」设计哲学——文件格式先是一串带长度标签的集装箱，解析器逐块读、不认识的块跳过，格式因此可以增量演进。音频处理更深的另一层——频域分析与降噪——在[谱减法那篇](/blog/articles/fft-spectral-subtraction/)里拆过：时域的 WAV 字节与频域的幅度谱，是同一份数据的两副面孔。
