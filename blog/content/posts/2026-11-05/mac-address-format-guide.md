## 同一块网卡，四张"身份证"

帮同事修网络打印机的下午，你在思科交换机上敲了 show mac address-table，输出里躺着一行 001A.2B3C.4D5E；让同事看手机「关于本机」，他念给你听的是 00:1A:2B:3C:4D:5E；再远程看那台 Windows 主机的 ipconfig /all，物理地址又成了 00-1A-2B-3C-4D-5E。三个地址对不上号，差点当成三台设备排查——其实它们是同一块网卡。

MAC 地址本质就是 48 位十六进制数，写法不同只是各家的排版习惯：

- **冒号分隔**（XX:XX:XX:XX:XX:XX）：IEEE 802 的写法，Linux 的 ip link、macOS 系统报告、Wireshark 抓包都是它
- **连字符分隔**（XX-XX-XX-XX-XX-XX）：Windows 的 ipconfig /all、网卡属性面板、不少蓝牙设备标签用它
- **点分**（XXXX.XXXX.XXXX）：思科 IOS 的习惯，show mac address-table、show arp 这类 show 命令输出里最常见
- **连续十六进制**（XXXXXXXXXXXX）：没有分隔符，注册表和部分软件日志里这样记

排查的第一步不是改配置，是先把这四张"身份证"统一成一种写法。

## 匹配失败的根源：分隔符、大小写与前导零

对格式的最常见姿势是 Ctrl+F 搜索，然后失败：交换机输出里是点分，你搜的是冒号；日志里全小写，你粘的是大写。分隔符和大小写，就是复制粘贴匹配失败的全部根源——地址本身一个字节都没差别。

## 这个地址该贴到哪里

格式统一之后，第二步是找对地方。手机的地址分两处：iPhone 在「设置 → 通用 → 关于本机 → 无线局域网地址」，连上 Wi-Fi 后当前网络详情里还能看到「私有无线局域网地址」；Android 在「设置 → 关于手机 → 状态信息」，或 WLAN 高级设置里。要贴进路由器后台的 MAC 过滤、门禁白名单、家长控制列表的，是这些界面里显示的地址，格式随你——多数后台只认字符不认分隔符，实在拿不准就先转换成后台示例的写法再粘。

Windows 这头有两个查看入口：命令行敲 ipconfig /all，看「物理地址」一行，天生就是连字符写法；不想敲命令的，设备管理器里打开网卡的属性，「高级」页里也找得到。采集齐了就到路由器后台动手：MAC 过滤、静态地址分配、家长控制的列表里，逐条把转换好的地址贴进去，保存后让设备重连一次验证生效。

拿到一串地址分不清谁是谁家的，交给{{< tool id="mac-vendor-lookup" >}}MAC 地址厂商查询{{< /tool >}}：MAC 前 3 字节是 IEEE 分配的厂商标识 OUI，后 3 字节才是厂商自己编的序列号，查一下前缀就知道这块网卡是哪家造的，还能顺手识别出随机化隐私 MAC、支持批量——网管收到一整页地址先过一遍，打印机、摄像头、员工手机就分出来了。

## MAC 对上了，往上一层继续查

有个边界值得记住：MAC 是二层地址，只在同一个局域网里有效。数据包一过路由器，源 MAC 就被替换成路由器接口的地址，公网那头的服务器根本看不到你的网卡 MAC。所以 MAC 对表只在同网段排查里有意义——确认"这台设备连在这个交换机这个口"；再往上追应用不通、访问异常，就得换 IP 层的工具：划网段、算可用主机范围用{{< tool id="ip-subnet-calculator" >}}IP 子网计算器{{< /tool >}}，日志里冒出陌生 IP 想知道归属和运营商用{{< tool id="ip-lookup" >}}IP 地址查询{{< /tool >}}，服务端口通不通交给{{< tool id="port-checker" >}}端口扫描器{{< /tool >}}。

## 地址"变了"，先查随机化再怀疑网卡

还有一类"格式坑"根本不在格式：地址自己变了。iOS、Android 和新版 Windows 默认开启 MAC 随机化——连每个 Wi-Fi 都用随机生成的地址，不用网卡真实 MAC，免得商场、机场拿 MAC 跨网络追踪你的行踪。这带来两个经典困惑：

- 做 MAC 绑定、白名单时，路由器上看到的是随机化后的「私有地址」，不是手机机身参数里那个硬件地址——绑硬件地址反而连不上
- 关掉再重开随机化，或重置网络设置后，私有地址会重新生成，原来白名单里的条目直接失效

所以路由器上某台设备的 MAC 和记录里对不上，先去系统的 Wi-Fi 详情里看「私有无线局域网地址」开关，别急着报修网卡。居家排查同理：访客 Wi-Fi 反复掉线的设备，多半是地址换了一轮。
