## 联调这一天，工具帮你想起来"下一步该干嘛"

前端的一天通常是被接口和文档填满的：后端甩来一段 JSON 让你定类型、要对着 Swagger 反复调字段、写个组件不确定哪些原生属性可继承、临时抓个别的浏览器的 UA 来复现 bug、把用户填的标题拼进 HTML 忘了转义直接 XSS。这些动作单看都不难，难的是**每天重复、每次现翻**。站内的[开发者工具箱（一）](https://www.util.cn/blog/articles/dev-toolbox-part1/)已经铺了一批编码和格式化底座，这篇往上补联调与文档这几块。全部在浏览器本地完成，代码和接口定义不经过服务器。

## 接口文档：从生成到规范落地

接口写完第一件事是出文档，否则三天后自己都忘了参数含义。[API文档生成](https://www.util.cn/tools/api-doc/) 把接口的路径、方法、请求参数、响应结构按模板整理成一份可读的文档，省去手写 Markdown 表格的重复劳动。要和后端、要和自动化工具对齐格式时，就用 [OpenAPI规范生成器](https://www.util.cn/tools/openapi-spec-generator/)——它按 OpenAPI 3.0 规范生成描述文件，支持导出 JSON 与 YAML。一份规范既是团队对齐字段的"合同"，也能喂给 Swagger UI 一类的查看器渲染成可交互的接口页，还能导进代码生成器自动出客户端。两者串起来就是"手写文档 → 规范化 → 交给工具链"的闭环，字段命名、必填项、枚举值这些在规范里定死，比散在聊天里口头约定可靠得多。

后端常常只给一段响应 JSON，前端要据此写类型定义。手敲 interface 费时还容易漏字段、猜错可空性。[JSON转TypeScript接口](https://www.util.cn/tools/json-to-typescript/) 粘一段真实响应，自动生成对应的 `interface` 与嵌套类型，数组、可选字段一并推断，改两下就能用。接口定义全程本地生成，**带 token 的示例响应也不会外传**。

## 拼查询与存片段：少敲键盘，少翻聊天记录

GraphQL 写长查询时，嵌套一层选几列、加个变量、带个 fragment，手敲很容易漏括号或写错字段名。[GraphQL查询构建器](https://www.util.cn/tools/graphql-query-builder/) 用可视化方式点选要查的字段和变更（mutation），**自动生成语法**——你只管决定取哪些数据，`query`、变量声明、缩进由工具补齐，生成完直接贴进客户端。

另一类高频动作是"这段代码我上个月写过"。防抖函数、日期格式化、正则、常用的 CSS 片段，散在聊天记录和各个项目的注释里，用的时候找半天。[代码片段管理器](https://www.util.cn/tools/code-snippet-manager/) 让你把常用片段保存下来，按语言和分类归档、支持搜索，需要时搜个关键词直接取。存下来的都是你自己写的通用片段，保存在本地。

## 组件分析：一个 HTML 元素到底能用哪些属性和事件

封装组件、写自定义标签、给第三方组件补无障碍属性的时候，最难查的是"这个原生元素本来就支持哪些 attribute、能监听哪些事件"。想给按钮加个无障碍标签，`aria-*` 有一堆，到底哪些对 `button` 有效、哪些是全局的？想在 `<img>` 上做懒加载，`loading` 属性浏览器支不支持、对应的 `load`/`error` 事件什么时候触发？这些散在 MDN 各页，翻起来零碎。

[Web组件分析器](https://www.util.cn/tools/web-component-analyzer/) 的做法是直接分析一个 HTML 元素，把**该元素可访问的属性、可监听的事件和当前支持情况**列出来。选定标签名，能继承的 HTML 全局属性、该元素特有的属性、可绑定的事件一屏看全，省掉在文档里来回跳。日常两个用途最典型：**写封装层时**对照它确认有没有漏透传关键属性（比如把 `disabled`、`autocomplete` 忘了往下传）；**补无障碍时**照它的清单给交互元素配齐 `role` 与 `aria-*`。分析在本地完成，贴进去的组件模板不外传。

## 复现环境与安全细节：UA、Emoji、转义

排查"只在某些设备/浏览器上出问题"的 bug，要伪造不同客户端的请求头来复现。[User-Agent生成器](https://www.util.cn/tools/user-agent-generator/) 按浏览器、版本、操作系统、移动设备拼出对应的 User-Agent 字符串，改一行请求头就能模拟 iPhone Safari 或老版 Chrome，不用再手写那串又长又容易拼错的 UA。

写 UI 文案、做运营活动、给按钮加个图标，找一个 emoji 常靠系统面板翻半天。[Emoji速查复制器](https://www.util.cn/tools/emoji-picker/) 按分类检索常用 emoji，点一下就复制，还会记录最近使用，做文案和写 commit 时的固定那几个表情抬手就来。

最容易被忽略、出问题时最疼的是**转义**。把用户输入直接拼进 HTML、塞进 JSON、或拼到 SQL 里，一个 `<` `"` `'` 就能让页面错乱，甚至留下注入漏洞。[文本转义工具](https://www.util.cn/tools/text-escape/) 覆盖 HTML/XML、JSON、SQL 的特殊字符转义与反转义：渲染前把尖括号和引号转义掉防 XSS，往 JSON 字段里塞带换行和引号的文本时先转义防格式错误，写查询语句时把敏感字符处理干净防注入。转义在本地算，待处理的内容不上传。

## 常见问题

### 内部接口文档和代码片段会不会泄露？

文档生成、规范化、JSON 转类型、转义、UA 生成、GraphQL 语法生成这些都在浏览器本地完成，不落服务器、不写日志；代码片段管理器和 emoji 记录也只存在你自己的浏览器里。真正敏感的接口鉴权信息、私有代码不会离开当前标签页。

### 生成的 OpenAPI 文件能直接对接现有工具链吗？

可以。OpenAPI 3.0 是通用规范，导出的 JSON/YAML 能喂给 Swagger UI 展示、导入 Postman/Apifox 调试，也能接代码生成器。生成后建议用你们后端实际的 base path、鉴权方式和字段命名再校一遍，规范文件只是骨架。

## 小结

联调与文档的一天，各有一款落点：**接口出文档交给 API 文档生成和 OpenAPI 规范生成器，看效果用 Swagger 查看器，写类型用 JSON 转 TypeScript，拼查询用 GraphQL 构建器，存通用代码用片段管理器，复现环境用 User-Agent 生成器，安全细节靠文本转义，找表情用 Emoji 速查器**。组件可继承哪些属性和事件、页面渲染对不对，再配 Web 组件分析器查。代码、接口定义和内部文档全程本地处理，公司项目的敏感数据照样只留在自己机器上。
