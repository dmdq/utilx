## chmod：九个勾选，告别"755 到底是什么"

每个用过 Linux 的人都背过 755 和 644，但能脱口说出"属组为什么是 5"的不多。chmod 的八进制其实就是一个加法：**r=4、w=2、x=1，三位各算各的**——755 = 属主 rwx(7) + 属组 r-x(5) + 其他 r-x(5)。

{{< tool id="chmod-calculator" >}}chmod 权限计算器{{< /tool >}}把这个加法做成了九宫格：Owner/Group/Others 三行、读写执行三列，勾选即得八进制、符号串（rwxr-xr-x）和逐位算式。它是**双向的**：粘一个 "rwxr-x---" 进去能反查出 750；内置 644/600/700 等七条预设，每条带使用场景（600 配私钥、644 配普通文件、777 红色警告）。生成命令时还有个贴心细节：勾选递归后，它给的不是危险的 `chmod -R`，而是**目录和文件分开的 find 命令**——文件不需要执行位，一刀切的 -R 是权限事故的经典来源。

## curl 构建器：Windows 的引号地狱有救了

手写 curl 最大的痛不是参数，是**引号转义**：POSIX 用单引号、Windows CMD 的双引号要 `\"`、PowerShell 5 还有 curl 别名陷阱。同一个 POST JSON 请求，三个平台三副面孔。

{{< tool id="curl-command-builder" >}}curl 命令构建器{{< /tool >}}用表单解决：方法、URL、请求头行（带 Authorization Bearer 快捷键）、body 四模式（JSON 会在本地先做格式校验）、query 参数自动拼接——右侧同时给出 **POSIX / Windows CMD / PowerShell / HTTPie 四个版本的命令**，各自的转义都已处理好，复制哪个平台就粘哪个终端。GET 请求自动省略 -X（惯例），HEAD 用 -I，multipart 自动切 -F。

要强调的是：它**只生成命令文本，不发送请求**——带 token 的 Authorization 头只出现在你的浏览器内存里，这和把 header 粘进各种"在线请求测试"网站是两种安全等级。反过来，拿到别人的 curl 想读代码的，站内有{{< tool id="curl-to-code" >}}curl 转代码{{< /tool >}}，一进一出正好配套。

## 关键词密度：写手和 SEO 的那道红线

文章为搜索而写时，"关键词该出现多少次"是个真问题：太少检索不到语义，太多触发堆砌惩罚。行业经验带是 **0.5%-2.5% 合理、5% 以上算堆砌风险**——注意这是经验口径，搜索引擎从没公布过官方阈值。

{{< tool id="keyword-density-checker" >}}关键词密度检查器{{< /tool >}}的口径很诚实：中文没有空格分词，它按 n-gram（1/2/3 字滑窗）统计并明确标注这个限制，内置六十个中英停用词剔除虚词。用法两条：一是**定向检查**——把目标词填进去，看次数、密度和四档判定徽章（偏弱/合理/偏高/堆砌）；二是**全文扫描**——Top50 词频表里任何超 5% 的词都会触发黄色警示条。发稿前三十秒，把"这篇文章到底在重复哪个词"变成一个有数字的答案。

## 三件工具的共同点

它们都是那种**每几个月用一次、每次三十秒、查完就关**的工具——但正因为低频，每次用的时候都想不起来上次怎么算的。做成勾选即得的样子，把"回忆"变成"确认"，就是这类经典小工具的全部价值。

## 常见问题

### chmod 递归为什么推荐 find 而不是 -R？

`chmod -R 755 dir` 会把目录下所有**文件**也加上执行位——执行位对文件意味着"可执行程序"，配置文件、日志全部中招。find 按 `-type d` 和 `-type f` 分开处理才干净，工具直接生成这两条命令。

### curl 生成的命令里有我的 token，会上传吗？

不会。整个构建过程在浏览器里完成，页面连"发送请求"的按钮都没有——它只产出文本。

### 关键词密度 5% 是官方标准吗？

不是，是 SEO 社区的经验共识。搜索引擎从未公布过密度阈值，这个数字的价值在于"明显超过它就该回头读一遍自己的文章了"——读起来都别扭的重复，算法多半也看得出来。
